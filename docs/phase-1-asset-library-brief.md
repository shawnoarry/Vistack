# 阶段 1 产品确认：资产库与单张详情

状态：已按推荐方案实施并验证

更新：2026-07-13 14:28

范围：资产库页面、图片卡片、批量选择、独立文件下载、单张详情

## 1. 本阶段目标

让用户能够快速完成四件事：找到需要的图、看清图片与生成信息、下载单张或任意多张、把图片送回创作台继续改图。

本阶段不修改生成请求、供应商适配、历史图片内容或 API 配置。

## 2. 现在是什么样子

- 资产库被包在一个大面板中，左侧筛选、收藏夹、概览又各自是卡片，层级较多。
- 每张图片卡片同时显示收藏、详情、作参考、加入画布、删除和分类选择，按钮权重接近。
- 下载只能进入详情后操作。
- 批量选择只能删除，不能下载。
- 单张详情顶部同时排列原图、下载、复制信息、作参考、加入画布、一键复用、删除当前图、删除整组和关闭，动作过多。
- 详情下方提示词只显示较小区域，图片、提示词、参数和操作没有形成稳定阅读顺序。
- 同一生成批次的多张图片共用收藏和分类，但界面看起来像在操作单张图片；下载和删除当前图却确实针对单张。

## 3. 建议的资产库页面

### 桌面端

```text
资产库      [搜索提示词/模型] [筛选] [排序] [批量选择]
────────────────────────────────────────────────────
收藏夹      [图片] [图片] [图片] [图片]
全部        [图片] [图片] [图片] [图片]
收藏        [图片] [图片] [图片] [图片]
分类...
```

- 移除包住整个页面的浮动大卡片，页面使用平整底层。
- 左侧只承担收藏夹和主要筛选，不再重复展示“筛选 + 概览 + 收藏夹”三套相似入口。
- 顶部提供搜索、生成类型筛选、收藏筛选和时间排序。
- 第一版搜索范围限定为提示词和模型，不增加复杂标签系统。
- 排序提供“最新优先”和“最早优先”。

### 手机端

```text
资产库                 [选择]
[搜索]
[筛选] [排序] [收藏夹]
图片网格（两列）
```

- 不显示常驻左侧栏，收藏夹进入筛选菜单。
- 批量选择工具栏固定在可见区域，不要求用户滚回页面顶部。

## 4. 建议的图片卡片

```text
┌──────────────────────┐
│ □              收藏☆ │
│                      │
│        图片          │
│                      │
├──────────────────────┤
│ 提示词，两行以内      │
│ 模型 · 时间 · 比例    │
│ [下载] [作参考] [更多]│
└──────────────────────┘
```

- 点击图片进入详情。
- “下载”和“作参考”是可见常用操作。
- “详情”不再单独占按钮，因为点击图片已经代表查看详情。
- “更多”内放置一键复用、加入画布、归类和删除。
- 删除与普通操作分组，避免误点。
- 桌面端悬停只增强按钮/边框，不抬升卡片；手机端操作始终可见。
- 图片继续使用稳定统一的缩略图比例，详情中显示完整原图，不采用高度不稳定的瀑布流。

## 5. 批量选择与下载

已确认采用方案 B：多选几张，就分别下载几张独立文件，不生成压缩包。

选择模式：

```text
已选择 5 张       [下载所选] [删除所选] [取消]
```

- 进入选择模式后，点击图片只切换选中状态，不打开详情。
- 使用明确复选标记和低强度选中边框；不改变卡片尺寸。
- “下载所选”只处理当前选中的图片。
- 下载过程中显示“正在发起 2/5”，操作区尺寸保持稳定。
- 完成后显示“已发起 5 个下载”；部分失败时显示“已发起 3 个，2 个失败”。
- 第一次多文件下载前提示浏览器可能询问是否允许多个下载。
- 文件名使用同一批时间前缀和编号，例如 `vistack-20260713-01.png`。
- 批量下载不改变收藏、分类、历史或当前选择。

## 6. 建议的单张详情

不再把所有动作挤在图片上方。桌面端使用接近全屏的“图片详情工作区”，手机端使用全屏详情。

### 桌面端

```text
┌──────────────────────────────┬──────────────────┐
│                              │ 图片 2/4      [×]│
│                              │ [下载] [作参考]  │
│          完整图片            │ [一键复用] [更多]│
│                              │──────────────────│
│                              │ 生成提示词       │
│                              │ 可复制/展开       │
├──────────────────────────────┤──────────────────│
│ 同批次缩略图                 │ 模型/尺寸/时间   │
│                              │ 生成诊断         │
└──────────────────────────────┴──────────────────┘
```

- 图片始终是第一视觉内容。
- 同批次缩略图只切换当前图片，不关闭详情。
- 下载只下载当前显示图片；“结果作参考”改成语义明确的“当前图作参考”。
- “一键复用”保留，但明确它会恢复整次生成的提示词、参考图和参数。
- 提示词提供复制和送回创作台编辑。
- 参数和诊断属于当前生成记录，诊断按钮在该记录内部。
- 加入画布、删除当前图和删除整组进入“更多”；删除仍保留现有确认保护。

### 手机端

- 顶部固定关闭按钮。
- 图片在上，下载/作参考紧随其后。
- 提示词、参数和诊断在下方展开，不横向挤压图片。
- 同批次缩略图横向滚动。

## 7. 收藏与分类的产品选择

当前收藏和分类属于“整次生成记录”，不是单张图片。建议本阶段先保持数据结构不变，但把文案说清楚：

- 卡片收藏改为“收藏本组”，或把收藏入口放到详情中的“整组信息”。
- 分类改为“本组收藏夹”，明确同一批次图片会一起归类。
- 单张下载、单张作参考和删除当前图仍针对当前图片。

推荐原因：本阶段不引入数据迁移，避免历史收藏和分类发生静默变化。以后如果确认必须逐张收藏/分类，再单独设计兼容旧数据的迁移方案。

备选方案是本阶段直接改成逐张收藏和分类，但需要扩展历史数据格式、定义旧记录如何继承，并增加迁移与回退工作，风险和范围明显更大。

## 8. 保持不变

- 所有现有历史图片、提示词、收藏和分类数据。
- 当前筛选结果和收藏夹能力。
- 单张下载、作参考、一键复用、加入画布和删除能力。
- 历史诊断脱敏规则。
- 浅色和深色主题。

## 9. 验收标准

- 用户可从卡片直接下载单张图片，不必先进入详情。
- 用户可任意选择多张并分别下载独立文件。
- 批量下载失败不会删除、取消收藏或改变历史记录。
- 桌面端选择工具栏在滚动图片列表时仍可操作。
- 手机端可以在不横向滚动页面的情况下选择、下载和退出选择。
- 详情中能快速找到当前图、下载、作参考、完整提示词、参数和对应诊断。
- 删除当前图和删除整组不会与常用操作混在同一按钮组。
- 所有历史记录与现有收藏/分类保持可读。
- `npm run check` 全部通过，并在桌面与手机视口进行浏览器验证。

3. 收藏与分类是否按推荐方案暂时保持“整组”语义，并在界面中明确说明。

## 11. 实施结果

- 资产页已改为平整页面骨架，桌面保留简洁侧栏，手机使用顶部筛选。
- 已加入提示词/模型搜索与最新/最早排序。
- 卡片已调整为图片优先，下载和作参考直接可见；复用、画布、整组归类和删除进入更多操作。
- 已加入任意多选后的独立文件下载、稳定编号文件名、进度与失败数量反馈。
- 单张详情已改为桌面分栏、手机全屏的图片详情工作区。
- 收藏与分类继续按整组保存，界面明确使用“收藏本组”“本组收藏夹”。
- 单张、整组和批量删除均有独立确认步骤。
- 历史数据格式、生成请求和供应商适配均未改变。
