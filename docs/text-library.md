# 拾句：本地文字库

## 本机独立版

已部署到 `D:\日历\拾句`，通过 `D:\日历\启动拾句.cmd` 启动。
独立版自带 Node.js 运行环境和构建后的页面，不依赖本项目目录。
数据位于工具目录的上一级，即 `D:\日历\text-library.json`。
下述 npm 命令用于源码开发，不能与独立版同时占用 4178 端口。

## 启动

双击项目根目录的 `start-text-library.cmd`，或运行 `npm run text-library`。
浏览器自动打开 `http://127.0.0.1:4178/text-library.html`。
关闭启动窗口会停止服务。它与 Vistack 生图界面相互独立，但共用项目的 Node.js 和 Vue 依赖。
端口占用时可运行 `npm run text-library -- --port 4179`。
后台测试时设置 `TEXT_LIBRARY_NO_OPEN=1`，不要使用 `--open false`（后者会被识别成页面路径）。

## 数据

默认保存到 `D:\日历\text-library.json`，界面的“数据与备份”显示完整路径。
每次成功写入前，将上一版复制为同目录的 `text-library.json.bak`。
采用临时文件写入后重命名；版本号防止多个窗口静默覆盖。
读取错误时禁止写入，不以空库覆盖损坏文件。
开发服务可通过 `TEXT_LIBRARY_PATH` 环境变量指定数据文件；独立版固定使用程序目录上一级的数据文件。
独立版可用 `TEXT_LIBRARY_PORT` 环境变量更换端口，默认 4178。
服务只绑定本机回环地址，拒绝跨源写入；不调用云端 API。

定期导出完整 JSON 备份。导入备份是增量合并，同正文保留已有记录和使用历史。
需要完整恢复旧版本时，先停止服务，保留现有数据文件，再用完整 JSON 备份替换数据文件。
单个 `.bak` 只保留上一版，不能代替历史备份。

## 使用

- 正文、国家或朝代、作者、作品、备注可编辑。
- 新收录粘贴、图片识字转入收录、批量文本预览会识别明确署名（破折号、国家/朝代、作者与书名组合）。未标明的单独人名仅在库中有同名作者时识别，不猜测普通短句。原始输入保留，可关闭识别或还原为正文。
- 分类可新增、改名、删除；旧库保留中国古诗词、西方文学、日式文学、中式随笔，空库没有预设分类。删除分类只将文字移到未归类，不删除文字。
- 可以先按作者或作品搜索，再把当前筛选结果批量归入某种文体。
- 搜索正文、国家或朝代、作者、作品、备注；兼容旧数据的标签检索。空格分隔的关键词需要全部匹配。
- 基于 Fuse.js 的近似匹配，可选内置主题近义词扩展；不是自然语言语义检索。
- 状态为未使用、待制作、已使用、不能用或退回、不建议用、待确认状态，可逐条手动更改并保留变更记录。
- 默认显示未使用；复制不会改变使用状态。旧文档已用记录不伪造使用日期。
- “复制文案”只复制正文并保留换行；“复制作者及出处”只复制 `[国家或朝代]作者《作品》`，不带 `——`，无作者或作品时不补空占位符。
- 美、日、英、韩对应的全称可规范为单字；俄罗斯、苏联、印尼等保留填写值，未知国家不猜测。
- 记录使用时填写日期和用途，可撤销单次使用；撤销最后一条记录时恢复记录使用前的状态。
- TXT 导入支持空行分条或每行一条，保留每条内部换行，不猜测作者。
- JSON 备份包含自定义分类名称及稳定 ID。导入时保留已有分类，新增不同名称的分类，同名分类合并；同 ID 不同名称会分配新 ID，不覆盖自己的分类。只含分类、没有新文案的备份也可导入。
- 重复检测忽略标点、空格和全半角差异，但不自动合并意思相近的不同句子。
- 勾选多条后“导出所选”，或“导出结果”导出筛选结果，可选 Markdown、Word DOCX 或 TXT；正文和署名分开，不带署名前的破折号。是否包含使用状态可选。
- “数据与备份”导出完整数据 JSON，包含备注、历史、原文溯源和全部使用状态，发给别人前应确认分享范围。
- “图片识字”选择图片后在本机运行简体中文和英文 OCR，允许修改识别结果，再进入收录表单。图片不上传，也不自动保存到库内。人名、生僻字及复杂排版需人工校对。
- 宣纸（暖纸白与墨绿）、海盐（浅灰绿与暖白）、胭脂（藕粉与暖白）三套浅色配色，覆盖侧栏、列表、正文与弹窗；左下角圆点切换，记住当前浏览器的选择，不改变数据文件。
- MuMu 自动采集、图片附件与日历助手联动尚未接入。

## 分享与更新

空库便携版只带程序、Node.js、离线识字资源、图标与启动器，不带 `text-library.json`、`.bak` 或原始文档。
同事解压整个文件夹后运行 `启动拾句.cmd`，无需安装开发环境；首次保存会在包的根目录生成自己的数据文件。
不要只分享快捷方式，也不要在压缩包内直接运行。程序适用于 Windows x64，需放在可写目录。
每个人的库相互独立，没有同步。后来收到 JSON 时再通过批量导入合并，不替换同事自己的库。
未来更新只替换程序子目录；保留根目录数据文件。升级前另做完整备份，不以“空库数据文件”覆盖旧库。

识字模型在源码第一次开发/构建前由 `prepareOcr.mjs` 下载并缓存到 `text-library-public/ocr`，Git 不跟踪这些大文件。
便携版已包含模型，正常识字不需要联网。程序源码可随 Vistack Git 提交，本机个人文字库和整理备份不在项目内。

## 旧文档整理

原 `.DOC` 文件不修改。只读副本、颜色审计和导入预览保存在 `D:\日历\整理备份`，不进入 Git 仓库。
先从办公软件只读提取 WordOpenXML，再生成保留段落位置、文本和文字颜色的审计 JSON。
`tools/text-library/importLegacyCli.ts` 将审计 JSON 转换为文字库导入预览。

- 黑色和深灰归未使用；蓝色系归已使用；绿色系归待制作；红色系归不能用或退回。
- 黄色、白色、不同状态色系混杂的正文归待确认，不从颜色推断“不建议用”。
- 合并明确的跨段正文与署名，保留原文、色号和全部重复位置。正文只去除采集标记、零宽符及列表编号，不润色错字。
- 同文异色按待确认优先，其次退回、已用、待制作、未用；署名不一致和长条目等标记待核对。
- 文体分类不以国籍强行推定，首次导入保留未归类，后续可逐条或批量修改。
- 自动分条和署名提取是初步整理，不代表已经完成逐条编辑校对。可在详情展开“旧文档原文”核对。
