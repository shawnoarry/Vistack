# Vistack UI/UX 产品规划

状态：阶段 1 已实施；原阶段 2 整页重排提案已撤回，其余内容仅作问题清单并需重新逐项规划

更新：2026-07-13

适用范围：创作台、结果区、资产库、历史详情、全局 API 配置、工具箱与画布入口

## 1. 产品方向

Vistack 当前最重要的用户任务是“改图”：选择 URL/配置、拉取模型、导入参考图、输入提示词、调整必要参数并生成。

界面方向定义为：**高频改图优先，结果就是资产，低频能力按需出现。**

本轮不是视觉换皮，也不删除功能。主要工作是重新安排信息层级、操作顺序和响应式布局，让常用操作更短，低频功能不再占据主流程。

## 2. 当前体验

### 全局结构

- 顶部同时显示品牌、模型、三个主导航、完整 Endpoint 和 API 配置按钮。
- API 配置展开后占据大幅页面高度，而且在创作台、资产库和工具箱中都会把主内容向下推。
- API 配置同时包含生图配置、预设管理、模型拉取和提示词助手配置，常用与低频设置混在一起。

### 创作台

- 桌面端同时展示参考图、合影助手、结果、画布切换、模型状态、请求诊断、提示词预览、近期资产和底部输入栏。
- 最新主图、任务结果和近期资产表达了相近信息，但没有形成一个明确的“当前选中结果”。
- 提示词输入虽然高频，却固定在底部并覆盖页面空间；在手机端需要经过参考图和低频合影助手后才能到达。
- 参数控件与模型兼容逻辑混合，用户难以判断哪些是当前模型真正需要的。

### 资产库与历史详情

- 资产库使用“外层大面板 + 左侧多个卡片 + 图片卡片”的多层边框结构，页面显得像被许多盒子包住。
- 图片卡片同时放置详情、作参考、加入画布、删除、收藏和分类，常用下载反而只在详情中出现。
- 批量选择目前只能批量删除，不能下载所选图片。
- 单张详情的图片、提示词、参数、诊断和大量动作缺少清晰主次。

### 工具箱与画布

- 五个工具、当前工具表单、可编辑提示词和工具结果同时平铺，但尚无经过验证的高频工作流。
- 画布作为创作台结果区的同级模式出现，视觉权重高于实际使用价值。

### 移动端

- 桌面三列结构主要变成长纵向堆叠，低频功能排在提示词和生成按钮之前。
- 顶部 Endpoint 和导航占用较多首屏空间。
- 主操作没有围绕手机使用顺序重新编排。

## 3. 目标信息架构

### 第一层：日常工作

- 创作台：导入参考图、写提示词、设置必要参数、生成、查看结果。
- 资产库：查找、筛选、下载、复用和管理历史图片。

### 第二层：上下文信息

- 当前模型和配置预设。
- 当前结果的提示词、参数和诊断。
- 任务进度与失败原因。

### 第三层：按需功能

- 高级 API 设置、提示词助手设置。
- 合影助手、模板和词组。
- 加入画布、工具箱实验能力。

## 4. 初版创作台构想（未批准，暂不执行）

本节是首次整体审查时形成的宽范围构想。用户已明确不希望重构整个创作台，因此它不再是阶段 2 的实施目标，只保留用于说明曾识别的问题。任何具体调整都必须按 [阶段 2：创作台小步调整](phase-2-studio-workflow-brief.md) 的方式重新拆分和确认。

### 桌面布局

```text
┌ Vistack ─ 创作台 / 资产库 / 工具箱 ─ [配置预设 / 模型] [设置] ┐
├──────────────┬─────────────────────────────┬───────────────┤
│ 参考图       │ 当前结果                    │ 结果信息      │
│ 上传/排序    │                             │ 提示词        │
│ 用途/名称    │        选中的大图           │ 参数/诊断     │
│              │                             │ 常用操作      │
│ 高级辅助 ▸   │ 当前批次 / 最近结果缩略图   │               │
├──────────────┴─────────────────────────────┴───────────────┤
│ 提示词输入                                      参数  生成 │
└────────────────────────────────────────────────────────────┘
```

调整原则：

- 顶部只保留当前预设/模型摘要，不常驻显示完整 Endpoint。
- API 配置改为独立设置面板，不再把所有页面内容整体向下推。
- 中央只保留一个明确的“当前结果”；当前批次和近期历史作为可切换缩略图。
- 右侧“提示词预览”改为“当前结果信息”。生成前只在需要时展示最终请求预览；生成后显示所选结果的提示词、参数和诊断。
- 合影助手改为满足条件后可展开的高级辅助，不占空状态主流程。
- 画布不再与“快速生成”同权重常驻；从具体图片的次级操作进入。
- 提示词与生成按钮保持可见，但固定在工作区内部，不遮挡整页内容。

### 手机布局

```text
[当前预设 / 模型] [设置]
[添加参考图]  已选图片横向列表
[提示词输入]
[必要参数] [生成]
[当前结果]
[本批次 / 最近结果]
[结果详情与诊断 ▸]
[高级辅助 ▸]
```

- 高频步骤必须排在低频助手之前。
- 参数只显示当前模型需要的项目，其余放入“更多参数”。
- 不把桌面右栏机械堆到页面底部；结果信息使用折叠区或底部抽屉。

## 5. 目标结果体验

- “当前结果”是唯一大图区域，不再同时保留语义重复的大主图和一次性瀑布流。
- 当前批次、最近生成和历史记录使用同一个持久结果来源；浏览器重开后仍可从历史恢复。
- 点击任一缩略图会同步切换大图、提示词、参数、诊断和操作。
- 任务进行中、失败和完成使用稳定的局部状态，不改变整体布局尺寸。
- 诊断信息属于具体任务/历史记录。主页面不再默认只代表最近一次请求。

## 6. 目标资产库

### 页面结构

```text
资产库       [搜索] [筛选] [排序] [批量选择]
收藏夹/分类  ───────────────────────────────
              图片网格
              图片网格
```

- 页面底层保持平整，只给真正独立的图片项使用卡片，不再把整个页面包成浮动卡片。
- 桌面端收藏夹可保留为窄侧栏；手机端改为筛选菜单，不形成长侧栏堆叠。
- 增加提示词/模型搜索和时间排序，方便长期管理大量结果。

### 图片卡片

- 图片是第一视觉内容，默认状态只显示必要信息。
- 点击图片打开详情；下载作为卡片可直接触达的常用操作。
- 收藏是持续状态，使用清晰但安静的标记。
- 作参考保留为主要复用操作。
- 加入画布和删除属于次级操作；删除必须与普通操作分组。

建议操作层级：

```text
[图片                         ☆]
[下载] [详情] [作参考] [更多]
                       ├ 加入画布
                       └ 删除
```

### 批量选择与下载

```text
已选择 5 张   [下载所选] [删除所选] [取消]
```

- 采用已确认的方案 B：选择几张，就分别发起几张独立图片下载，不创建压缩包。
- 显示“正在发起 2/5”和最终成功/失败数量。
- 提示浏览器可能要求允许多个文件下载。
- 稳定编号文件名，避免覆盖或无法区分。
- 下载不修改收藏、分类、历史或图片内容。

## 7. 目标单张详情

桌面端建议使用右侧详情抽屉，手机端使用全屏详情页；避免在大图上叠加拥挤的多行工具栏。

信息顺序：

1. 图片与同批次切换。
2. 下载、作参考、再次使用等高频动作。
3. 完整提示词，可复制和送回创作台编辑。
4. 模型、尺寸、时间、来源和保存状态。
5. 对应本次生成的诊断信息。
6. 加入画布、删除等次级或危险动作。

## 8. API 与模型参数

- 顶部提供快速切换配置预设、当前模型和刷新模型列表的紧凑入口。
- 完整 URL、Key、代理与提示词助手配置进入设置面板。
- 参数区域由“模型能力配置”决定显示内容：已知模型显示专用参数，未知模型显示通用兜底。
- 不尝试一次性猜中所有上游；每次真实兼容问题沉淀为可测试的模型/供应商配置。
- 不改变现有供应商请求行为，直到对应适配方案单独确认。

## 9. 工具箱与画布定位

以下内容只是待验证假设，不代表已决定调整入口或界面。必须先定义画布和工具箱分别解决什么任务，再单独形成产品方案。

- 当前阶段停止继续堆叠工具功能，只修阻断问题。
- 工具箱保留入口，但后续先验证每个工具解决的具体任务，再决定是独立工作流还是融入创作台。
- 图片反推更可能成为提示词输入旁的辅助动作，而不是独立工作台。
- 画布更可能成为从结果/资产进入的深度整理工具，而不是日常生成的同级模式。
- 工具箱和画布的最终架构必须另开产品方案确认，不能在本轮主界面调整中顺带决定。

## 10. 不变项与风险边界

保持不变：

- 历史图片、提示词、收藏、分类和 API 配置数据。
- 已调试的供应商路由、请求格式和模型尺寸逻辑。
- 单张图片下载、再次生成、作参考等已有能力。
- 浅色/深色主题和桌面/移动端支持。

实施边界：

- 不做破坏性数据迁移。
- 不一次性重写整个 `App.vue`。
- 不在同一阶段同时调整布局和供应商请求逻辑。
- 任一阶段发现用户流程与已确认方案不同，暂停并重新确认。

## 12. 总体验收标准

- 1440×900 桌面视口中，高频改图入口、当前结果和生成操作具有明确第一层级。
- 手机端提示词和生成按钮必须出现在合影、模板、诊断等低频功能之前。
- 资产库可直接下载单张图片，并分别下载任意选中的图片。
- 单张详情能清楚回答：这是什么图、用什么生成、提示词是什么、如何下载/复用、如何复制对应诊断。
- 主图与结果列表不再重复表达同一批内容；刷新后最近结果仍可从历史恢复。
- 未知上游仍可使用通用参数，不因能力配置缺失而阻断生成。
- 所有既有历史、提示词和 API 配置保持可读，不发生静默删除或覆盖。
