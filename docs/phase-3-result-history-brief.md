# 阶段 3 产品确认：结果与历史统一

状态：已按推荐方案实施并验证

更新：2026-07-16

范围：创作台快速生成结果区、近期生成历史、所选生成诊断，以及为这些界面补充的可选历史字段

## 1. 本阶段目标

让创作台围绕一条清楚的主线工作：当前正在看的图是哪一张、它属于哪次生成、当时用了什么提示词和参数、如何下载或继续改图、出现问题时如何复制这一次生成的诊断。

本阶段只整理结果与历史的关系，不重构整个创作台，不改变三栏结构和固定底部提示词栏，也不同时启动模型参数适配、Responses API、参考图粘贴/排序、工具箱或画布改造。

## 2. 现在是什么样子

- 一次生成多张图片时，中间区域会同时铺开多张大图，下面又显示同一批图片的缩略图，内容重复。
- 已完成任务仍可能以任务卡片显示，右侧又有“近期资产”，同一批结果在多个位置重复出现。
- 关闭浏览器后，历史记录虽然仍在资产库和右侧近期资产中，但中间结果区不会自动恢复最近结果。
- 中间图片的常用操作主要依赖鼠标悬停；当前查看哪张图、属于哪次生成，不够明确。
- 右侧“请求诊断”根据现在表单里的模型、参数和最近一次请求计算，不一定对应用户正在查看的历史图片。
- 点击历史“查看”会恢复结果，同时改动部分创作台参数。浏览旧图和复用旧配置没有被清楚区分。
- 成功历史已经保存提示词、模型、比例、尺寸、端点、参考图配方等信息，但还没有稳定保存实际发送参数、耗时、上游修订提示词和脱敏错误摘要。

## 3. 推荐的整体结构

沿用现有桌面三栏，不搬动左侧参考图、右侧模型状态和底部提示词输入。只把中间结果区和右侧“近期资产”整理成一套主从关系。

### 桌面端

```text
中间：当前结果                              右侧：生成历史
┌──────────────────────────────────┐       ┌────────────────────┐
│ 文生图 · 16:03 · 图 2/4           │       │ [缩略图] 文生图 16:03│
│ [下载] [作为参考图] [复用本次] […]│       │ [缩略图] 图生图 15:41│
├──────────────────────────────────┤       │ [缩略图] 图生图 昨天 │
│                                  │       │                    │
│            当前图片              │       │ [进入资产库]        │
│                                  │       └────────────────────┘
├──────────────────────────────────┤
│ [1] [2 已选] [3] [4]             │
├──────────────────────────────────┤
│ 提示词 · 模型 · 比例 · 尺寸 · 耗时│
└──────────────────────────────────┘
```

- 中间始终只显示一张“当前图片”，不再把同批图片全部铺成大图。
- 同一批生成多张图片时，在主图下方显示稳定尺寸的横向缩略图；点击只切换当前图片。
- 下载、作为参考图、放大和复用本次保持直接可见，不依赖悬停才出现。加入画布等低频动作可进入“更多”。
- 右侧“近期资产”改为紧凑的“生成历史”，保留最近若干生成组和进入完整资产库的入口，不再在每条记录上重复排列一组操作按钮。
- 点击右侧历史记录只切换中间正在查看的结果和信息，不修改现在正在编辑的提示词、参考图或参数。
- 只有点击“复用本次”才把该记录的提示词、参考图和可恢复参数带回输入区。
- 新生成完成后自动选中该生成的第一张图；用户随后可以继续切换同批图片或历史记录。

### 手机端

- 仍按现有页面顺序展示，不重排整个创作台。
- 当前图在上，同批缩略图横向滚动，常用操作紧随图片，不使用只能悬停看到的按钮。
- 生成历史在结果信息之后以紧凑列表展示；完整管理仍进入资产库。
- 页面不产生横向滚动，固定底栏不遮挡结果操作和历史列表。

## 4. 任务队列与历史的分工

- 任务区只表达“正在生成”和“本次会话内失败”的任务状态，不再作为第二套已完成图片瀑布流。
- 成功任务完成后进入持久历史，并自动成为当前结果。
- 失败任务保留错误状态和对应诊断，用户可以复制后重试或关闭；本阶段不把无图片的失败任务混入资产库。
- 失败任务暂不承诺跨浏览器重启保留。完整的持久失败日志需要单独的数据与清理规则，不在本阶段扩张范围。

这样可以同时保留多任务状态能力，又不会让“任务卡片、主图、缩略图、近期资产”四处重复显示同一批成功结果。

## 5. 选中结果后哪些内容会一起变化

“选中”只表示正在查看，不表示重新提交或复用。选择某次历史生成后，以下内容必须来自同一条记录：

- 当前主图和同批缩略图。
- 生成类型、时间、当前图片序号。
- 当时保存的提示词；有上游修订提示词时同时提供查看。
- 模型、供应商路由、比例、尺寸、张数、批量方式和可用的实际发送参数。
- 下载当前图、作为参考图、放大、复用本次、加入画布等操作目标。
- 复制诊断信息的记录 ID、时间、端点、模型、参数、参考图数量、耗时、保存警告和脱敏错误摘要。

不存在的旧字段显示“未记录”，不能拿当前表单值冒充历史值。

右侧原有“提示词预览”继续表示下一次请求会提交的内容，本阶段不删除也不重新定义。为避免混淆，历史提示词只显示在当前结果的信息区。

## 6. 浏览器重开后的恢复规则

- 读取历史完成后，中间结果区默认显示最新一条仍有可用图片的历史记录。
- 恢复只发生在显示层，不自动覆盖用户本地保存的提示词草稿、参考图、当前模型或参数。
- 如果最新记录的部分图片无法读取，继续尝试该组其他图片；整组不可用时选择下一条可用历史，并显示非破坏性提示。
- 没有历史时保留现有空状态，不创建虚假结果。
- 用户删除当前图片或整组记录后，选择相邻的可用记录；删除仍沿用已有确认保护。

## 7. 诊断改成“属于这次生成”

右侧诊断使用两种明确状态：

1. 已选中结果或失败任务时，标题为“所选生成诊断”，复制内容必须来自该记录或该任务的诊断快照。
2. 尚无可选结果时，标题为“下一次请求检查”，继续显示当前表单预计使用的路由和参数。

用户切换历史记录后，诊断同步切换。复制按钮不能继续默认复制最近一次请求，也不能把当前表单参数拼到旧记录中。

诊断在保存和复制两个阶段都要脱敏。API Key、Bearer Token、代理密码、带密钥的查询参数和参考图原始数据不能进入历史或剪贴板。

## 8. 建议补充的可选历史字段

现有 `GenerationHistoryItem` 字段全部保留，只增加可选字段；旧记录不迁移也必须继续读取。

```text
actualParams?            实际路由和实际发送的安全参数快照
imageDetails?            每张返回图可选的实际参数与修订提示词
revisedPrompt?           上游返回的整组修订提示词
durationMs?              从提交到完成或失败的耗时
redactedErrorSummary?    经过脱敏和长度限制的上游错误摘要
```

`actualParams` 只记录允许展示的字段，例如供应商模式、脱敏后的最终端点、请求次数、`n`、比例、尺寸、输出尺寸、质量、自动提示词、翻译、参考图数量和参考图负载位置。供应商没有返回的字段保持缺失，不猜测补值。

`imageDetails` 按图片序号对应，允许上游在每张图返回不同参数或 `revisedPrompt`；没有逐图差异时无需重复存储。

当前会话中的 `GenerationTask` 同样增加可选诊断快照，让失败任务可以复制自己的错误诊断。现有生成请求对象和发给上游的请求体保持完全不变。

## 9. 明确保持不变

- 创作台三栏结构、快速生成/画布入口和 PC 固定底部提示词栏。
- 图生图、文生图按钮名称和现有切换规则。
- 词组、模板、合影助手、保存模板、AI 优化和翻译入口。
- 参考图上传、用途标记、顺序、提示词拼接和供应商专用行为。
- API 配置、模型拉取、API 预设和本地保存方式。
- 资产库已完成的单张下载、任意多选下载、详情、收藏和分类。
- 历史图片、提示词、配方、收藏、分类、画布数据和现有 IndexedDB 数据库。
- Responses API、参考图粘贴/排序、模型能力配置、Storage v2、工具箱和画布架构。
- 现有浅色/深色主题和整体视觉语言；本阶段不换配色、字体或做全界面美化。

## 10. 数据安全与兼容规则

- 新字段全部可选，读取旧历史时按缺失字段处理，不能报错或覆盖旧记录。
- 不执行清空历史、重建数据库或先删后迁移；本阶段不提高数据库版本，除非实施时确认新增索引确实必要。
- 加载历史、选择历史和恢复最近结果都是只读行为。
- 写入新记录失败时保留当前可见生成结果并明确提示，不删除已有历史。
- 任何新增诊断字段在落盘前先经过白名单筛选和敏感信息脱敏。
- 不改变现有请求体、请求次数策略、供应商路由或失败重试规则。

## 11. 实施顺序

获得一次整体确认后，按以下顺序连续实施，不再逐项等待产品决定：

1. 增加旧历史兼容、诊断脱敏和“选择不回填表单”的行为测试。
2. 给任务与历史增加可选诊断快照、耗时和返回参数字段，并在请求完成/失败时采集。
3. 建立独立的“当前所选生成/图片”状态，不再借用输入表单状态表达浏览状态。
4. 把结果区改成单张当前图、同批缩略图、固定操作栏和结果信息区。
5. 把右侧近期资产改成紧凑生成历史；成功任务进入历史，任务区只保留进行中和失败。
6. 加入重开后恢复最新可用结果，以及删除当前结果后的安全选择规则。
7. 运行完整检查，并验证桌面、窄桌面和手机视口；更新项目进度并建立独立提交检查点。

如果实施中发现会改变请求体、需要删除/迁移旧数据，或必须扩大到工具箱/画布，立即停下并重新说明，不自行扩大范围。

## 12. 验收标准

- 一次生成四张图时，中间只有一张大图和四个缩略图，不再出现四张大图加四个缩略图的重复布局。
- 新生成完成后自动成为当前结果，下载按钮只下载当前所选图片。
- 点击任意历史记录后，主图、同批图片、提示词、参数、操作和诊断来自同一次生成。
- 点击历史只浏览；点击“复用本次”才回填提示词、参考图和参数。
- 关闭并重新打开浏览器后，最新可用历史自动出现在当前结果区。
- 进行中和失败任务仍可见；成功结果不再同时占据任务卡片和历史列表。
- 失败任务能复制自己的诊断，切换历史后能复制所选历史的诊断。
- 旧历史缺少新字段时仍可查看、下载、作参考和复用，并明确显示“未记录”。
- API Key、Bearer Token、代理密码和参考图数据不出现在历史诊断中。
- 现有请求体和供应商路由行为测试保持不变。
- 历史图片、提示词、API 预设和其他本地数据没有被清空、覆盖或静默丢失。
- `npm run check` 全部通过，并至少验证 1440×900、1280×800、1024×768 和 390×844。

## 13. 唯一确认项

用户已于 2026-07-16 明确确认按整套推荐方案实施阶段 3。

确认覆盖文档中的布局、交互、兼容边界和实施顺序；实施过程中没有发生请求行为变化、破坏性迁移或工具箱/画布范围扩张。

## 14. 实施结果

- 中间结果区已改为一张当前图片、同批横向缩略图、固定常用操作和对应提示词/参数信息。
- 右侧近期资产已改为紧凑生成历史；点击历史只切换浏览状态，不会覆盖未提交提示词、参考图或参数。
- 浏览器重开后会选择最新一条仍有图片的历史记录；删除当前图片或整组后会安全选择可用记录。
- 成功任务进入持久历史，任务区只显示进行中和本次会话失败；失败任务可选择并复制自己的诊断。
- 诊断会跟随所选历史或失败任务；没有所选记录时才显示下一次请求检查。
- 历史和任务增加了可选 `actualParams`、`imageDetails`、`revisedPrompt`、`durationMs` 和 `redactedErrorSummary`，旧记录无需迁移。
- OpenAI 兼容响应中的 `revised_prompt` 会在存在时采集；新增逻辑只扩展响应读取，不改变任何请求体或供应商路由。
- 新增实际参数白名单、URL/文本脱敏和错误摘要长度限制；诊断明细同样会再次脱敏。
- 桌面底栏预留空间调整为 300px，确保 1024px 宽度滚动到底时历史内容完整位于固定底栏上方。

验证结果：

- `npm run check` 通过：8 个测试文件、45 项测试、类型检查和生产构建全部成功。
- 自动浏览器验证 1440×900、1280×800、1024×768 和 390×844 均无横向溢出。
- 四图记录始终只有一张主图、四个缩略图、一个历史选中态和一个缩略图选中态。
- 切换历史后未提交提示词草稿保持不变；重载后最新持久历史自动恢复。
- 复制所选历史诊断包含对应记录 ID 和耗时，测试 URL 中的 token 被脱敏。
- 1440、1024 和 390 结果/历史浏览流程未出现控制台警告或页面错误。
