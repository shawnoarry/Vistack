# 阶段 3 产品确认：持久瀑布流与失败任务记录

状态：已按用户确认的纠偏方案实施并验证

更新：2026-07-17

范围：创作台结果瀑布流、图片在创作台的显示状态、进行中/失败任务、失败记录、资产库恢复入口和对应诊断

## 1. 为什么调整

阶段 3 的第一版把创作台改成了“单一主图 + 同批缩略图”。它解决了主图和瀑布流重复的问题，但也让原本可以连续浏览多张结果的瀑布流失去价值，并让失败卡片比成功图片更容易长期占据页面。

用户随后明确了最终方向：

- 瀑布流仍然是创作台查看生成结果的主要方式，不能退化成单图查看器。
- 已生成图片要在关闭并重新打开浏览器后继续出现。
- 每张图片可以从瀑布流单独关闭，但关闭只影响创作台展示，不能删除资产。
- 被隐藏的图片仍能从资产库找到并恢复到创作台。
- 失败结果没有图片，不应成为资产；它们应作为任务和诊断记录管理。

因此，“单一主图 + 缩略图”方案已作废，以下内容是阶段 3 的最终产品与交接基线。

## 2. 最终结构

```text
创作台中间结果区
├─ 进行中 / 本次失败任务（紧凑任务区）
├─ 持久瀑布流（成功图片的主要浏览区）
│  ├─ 图片卡片：下载 / 作参考 / 复用 / 从瀑布流隐藏
│  └─ 按生成历史持续加载更早结果
└─ 失败记录（可折叠、最多 20 条）

资产库
├─ 保留全部成功图片，包括创作台已隐藏的图片
├─ 标记“创作台已隐藏”
└─ 可恢复显示，也可沿用原有确认流程真正删除资产
```

创作台不再额外保留一张独立大主图，也不再用同批缩略图重复展示相同结果。成功图片只在持久瀑布流中出现一次。

## 3. 成功图片与瀑布流

- 新生成成功后，图片先按原有方式写入持久历史，再出现在瀑布流中。
- 浏览器重开后，瀑布流从历史记录恢复，不依赖本次页面会话的内存状态。
- 默认加载最近 12 组仍有可见图片的生成历史；用户可点击“加载更早结果”继续浏览。
- 同一批生成的多张图片按各自自然比例展示，不强制裁成统一高度。
- 响应式列数为：1440px 两列、1280px 两列、1024px 两列、390px 单列。
- 卡片上的下载、作参考和复用操作保持直接可见，不要求先进入详情或依赖鼠标悬停。
- 右侧生成历史改为定位入口：点击后滚动并高亮瀑布流中的对应生成组，不再用历史点击替换中间内容。

## 4. “关闭”图片的准确含义

瀑布流图片右上角的关闭按钮表示“从创作台瀑布流隐藏”，不是删除：

- 隐藏状态会持久保存，重开浏览器后该图片仍不出现在创作台。
- 隐藏不会删除图片、提示词、生成参数、诊断或生成组记录。
- 资产库仍显示该图片，并用“创作台已隐藏”说明当前状态。
- 用户可从资产卡片菜单或资产详情点击“在创作台显示”恢复。
- 刚隐藏后提供短时撤销入口，降低误操作成本。
- 如果一组图片全部被隐藏，该组不占据创作台瀑布流，但完整资产仍保留在资产库。
- 真正删除当前图片、整组或批量资产时，仍沿用资产库已有的明确删除动作和确认保护。

历史记录只新增可选的 `hiddenImageIndexes` 字段。旧记录没有这个字段时，默认所有图片都在创作台显示，不需要迁移数据库。

## 5. 进行中与失败任务

任务和资产按是否产生有效图片分开：

- 进行中的生成保留在紧凑任务区，继续显示进度。
- 成功后任务离开任务区，图片进入持久历史和瀑布流。
- 失败任务留在任务区，提供“复制本次诊断”和“关闭”。
- “复制本次诊断”一次点击直接复制该任务自己的脱敏诊断，不再要求到右侧二次点击。
- “关闭”立即移除可见失败卡片，并清除创作台或工具箱中对应的当前错误提示。
- 关闭失败卡片不会把失败项变成资产，也不会删除下面的独立失败记录。

## 6. 独立失败记录

失败诊断需要可追溯，但不能无限占据主要结果区。最终规则是：

- 失败记录保存在当前浏览器本地，浏览器重开后仍可查看。
- 最多保留最近 20 条，超过后自动淘汰最旧记录。
- 记录区默认紧凑、可折叠，不和成功图片争夺主要视觉空间。
- 每条记录可复制诊断、复用当时提示词与可恢复参数，或单独删除。
- 保存内容仅包括提示词、模型、脱敏端点、安全参数、耗时和脱敏错误摘要。
- API Key、Bearer Token、代理密钥、参考图原始数据和其他原始秘密不得进入记录或剪贴板。
- 失败记录不是资产，不进入资产库，也不参与图片收藏、分类或下载。

## 7. 明确保持不变

- 创作台三栏结构和 PC 固定底部提示词栏。
- `图生图`、`文生图`的名称、判断和既有请求路径。
- 提示词草稿、词组、模板、合影助手、日历插画助手、AI 优化和翻译入口。
- 参考图上传、用途标记、顺序、提示词拼接和供应商专用行为。
- API 配置、模型拉取、API 预设及其浏览器本地保存方式。
- 资产库单张下载、任意多选下载、详情、收藏、分类和原有删除能力。
- 历史图片、提示词、配方、收藏、分类、画布数据和现有 IndexedDB 数据库。
- 生成请求体、请求次数、供应商路由和失败重试策略。
- Responses API、模型能力配置、Storage v2、工具箱和画布架构仍属于后续独立阶段。

## 8. 数据安全与兼容

- 不提高 IndexedDB 版本，不清空、不重建、不先删后迁移历史数据。
- `hiddenImageIndexes` 是可选显示字段；它只控制创作台可见性。
- 删除某张资产时会同步重排隐藏索引，避免隐藏状态错误地落到相邻图片。
- 写入历史和待恢复任务前，把 Vue 响应式对象转换为普通可克隆数据，避免 IndexedDB `DataCloneError` 导致隐藏状态或任务状态未保存。
- 失败记录使用独立本地键保存，并执行数量上限、字段白名单和脱敏。
- 历史写入失败时不能删除现有历史或已生成图片。

## 9. 验收结果

- 四张成功图片在创作台只以四张瀑布流卡片出现，没有额外主图或同批缩略图重复。
- 图片保持自然比例，1440x900、1280x800、1024x768 和 390x844 均无横向溢出。
- 单张隐藏后瀑布流从 4 张变为 3 张，刷新后隐藏状态仍然存在。
- 资产库仍保留全部 4 张图片，并能从详情恢复隐藏图片；恢复后创作台重新显示 4 张。
- 失败任务可直接复制自身诊断，测试密钥没有进入剪贴板。
- 关闭失败任务会移除任务/错误，失败记录仍存在并能跨刷新读取。
- 测试结束后已删除临时资产、失败记录、测试密钥和测试端点，没有把浏览器测试数据留给用户。
- `npm run check` 通过：类型检查、11 个测试文件、61 项测试和生产构建全部成功。
