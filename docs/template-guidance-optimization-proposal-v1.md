# 模板说明、素材提醒与词组优化建议（第一版）

状态：优化建议第一版，待评审；除“游戏素材”的准入边界外，本文内容尚未全部确认，也不代表已经批准实施

整理时间：2026-09-01

## 文档目的

本文整理 Vistack 模板使用说明、参考素材提醒和词组质量的候选优化方向，供后续讨论、试点和取舍使用。

本文不是完整需求定稿，不是实施承诺，也不表示所有建议都会进入产品。后续只有经过单独确认的项目才进入开发；未确认项目继续保留为研究建议。

## 已确认边界

以下边界已在当前讨论中明确，应作为后续工作的前提：

- 保留现有短提示词简单、易读、易修改以及较容易兼容已适配上游的优势。
- 不全面重构现有模板，不批量改写已有模板正文。
- 不改变模板点击、插入、编辑和最终提交的基本流程。
- 不改变现有上游请求格式和模型调用方式。
- 外部技能、提示词库和成图案例可以继续研究，也可以用于改善 Vistack 的通用能力。
- 外部内容不会因为被研究或验证，就自动并入任一模板分类。
- “游戏素材”菜单专门服务用户个人游戏项目。只有用户明确要求加入的提示词模板，才能进入“游戏素材”菜单。
- “游戏素材”的准入规则不限制外部资源用于其他 Vistack 通用功能、公共模板候选、词组候选或研究记录。

## 当前基础

当前项目已经出现以下相关能力或变更方向：

- 模板仍以可直接插入和编辑的提示词为核心。
- 模板数据开始支持可选的 `usageGuide`，可用于解释模板的组合方式。
- 短词组与 Prompt Pool 已经分开：前者适合轻量补充，后者适合追加成段描述。
- “游戏素材”已经作为独立菜单出现，当前内容应继续遵守人工明确准入规则。
- 原有模板和分类不需要为了本建议进行全量迁移。

## 优化目标

- 让用户更容易理解某个模板应该怎样补充和修改。
- 在缺少参考素材时解释可能影响，而不是简单阻止用户继续。
- 让新增词组在单独点击后也能产生明确、可预期的效果。
- 保持模板正文简洁，把复杂能力放在可选说明、提醒和词组中。
- 为外部研究内容建立独立的核验和采用路径，避免研究资料直接污染正式模板库。

## 非目标

本建议第一版不主张：

- 把所有模板改造成结构化表单。
- 强制所有模板声明参考图数量。
- 统一要求用户上传三张或更多参考图。
- 为所有模板增加复杂的输入字段、保留规则和修改规则。
- 自动扩写或重写用户最终提示词。
- 把外部技能整包安装进 Vistack 的模板系统。
- 直接复制许可证不明的技能或提示词正文。
- 未经用户明确要求，把任何新提示词加入“游戏素材”。

## 建议一：渐进补充使用说明

### 建议内容

沿用可选的 `usageGuide`。只对组合方式不明显、依赖前置描述或容易误用的模板显示简短使用说明。

示例：

```text
人物可见特征 + 当前固定风格段
```

```text
上传角色参考图后插入；可继续修改服装、姿势和场景
```

### 建议约束

- `usageGuide` 不进入最终提示词。
- 没有使用说明的旧模板保持原样。
- 使用说明应说明操作或组合关系，避免重复模板描述。
- 不把使用说明扩展成长篇教程或复杂字段表。

### 待确认事项

- 是否需要统一文案格式。
- 使用说明显示在模板卡片、插入后提示，还是仅保留当前卡片位置。
- 哪些现有模板值得补充，哪些应继续保持极简。

## 建议二：非阻断式参考素材提醒

### 建议内容

只为确实依赖或明显受益于参考素材的模板增加可选提示。提醒应说明缺少素材会带来的具体影响，并允许用户继续。

候选素材角色包括：

- 人物或主体身份参考。
- 页面或画面布局参考。
- 视觉风格参考。
- 材质与组件参考。
- 已确认的同系列结果参考。

候选最小数据结构：

```ts
referenceHint?: {
    recommended: number
    required?: number
    roles?: string[]
    message: string
}
```

这只是第一版讨论结构，并未确认应按此实现。

### 候选交互

- 推荐素材不足：显示轻提示，允许继续插入。
- 真正必要的素材不足：说明无法稳定完成的部分，并提供继续插入或返回补充素材的选择。
- 多参考任务：提示缺少的是哪一种素材职责，而不是只显示数量不足。
- 普通文本模板：不显示参考素材提醒。
- 参考图可能包含水印、色板、调试文字或其他污染时，提示这些内容可能传播到结果。

### 待确认事项

- 当前上传区是否已经能可靠识别素材数量和用途。
- 是否真的存在需要硬性 `required` 的模板，还是第一版全部采用推荐提醒。
- 提醒出现时机是选择模板、插入模板还是提交生成之前。
- 如何避免同一提醒重复打扰用户。

## 建议三：提高词组的独立有效性

### 建议内容

外部游戏 UI 技能、Nano Banana 案例和 GPT Image 2 案例优先用于提炼可选词组，而不是用于重写现有模板正文。

新增词组应描述可观察结果，例如：

```text
所有组件完整独立，保持充足间距，禁止边缘粘连。
```

```text
关键 HUD 位于屏幕安全区内，不遮挡核心操作区域。
```

```text
选中状态同时使用清晰轮廓、亮度变化和轻微缩放，不只依赖颜色。
```

```text
继承参考页面的按钮比例、图标语言、材质和光向。
```

### 候选分类

- 页面与信息层级。
- HUD 可读性与安全区。
- 组件独立、透明背景与切图友好性。
- 普通、悬停、聚焦、按下、禁用、锁定和冷却状态。
- 参考图身份、布局和风格一致性。
- 文字与装饰底板分离。
- 同系列页面或素材的视觉继承。
- 乱码、粘连、遮挡、错误透视和过度拥挤等负面约束。

### 质量标准

- 单独插入时语义完整。
- 用户可以直接修改或删除其中一部分。
- 尽量避免只有“高级、精致、专业”等不可验证的抽象形容词。
- 不默认引用或模仿受版权保护的具体游戏作品。
- 短词组保持简洁；只有需要多条关联规则时才进入 Prompt Pool。

### 待确认事项

- 首批词组覆盖游戏 UI、游戏素材生产，还是先做更通用的参考一致性和组件生成。
- 是否需要为不同模型提供不同版本。
- 如何通过实际生成对比判断词组确实有效。

## 建议四：建立外部资源研究台账

### 建议内容

将外部技能和提示词库保存在独立研究记录中，不直接混入运行时模板数据。

每个资源建议记录：

- 名称、链接和资源类型。
- 适用模型与覆盖范围。
- 是否提供真实输入、完整提示词和最终输出。
- 许可证及可复制范围。
- 可借鉴的方法、字段或词组方向。
- 明确不应采用的内容。
- Vistack 的核验和采用状态。

候选研究状态：

```text
待研究 -> 已核验 -> 已改写 -> 已测试 -> 可公开使用
```

“游戏素材”不使用以上状态自动准入。它始终增加一道独立人工条件：

```text
仅在用户明确要求加入“游戏素材”后，才允许写入对应菜单。
```

### 待确认事项

- 台账采用 Markdown、JSON 还是两者结合。
- 是否需要在正式模板数据中保留不可见的来源标识。
- 公共模板候选达到何种测试标准后才能进入产品。

## 候选实施阶段

以下阶段只是推荐顺序，不代表已经批准排期。

### 阶段 A：巩固使用说明

- 完成 `usageGuide` 的展示、空值兼容和移动端检查。
- 选择少量模板验证说明是否真正有帮助。
- 不批量补写旧模板。

验收候选：

- 旧模板无需迁移。
- 使用说明不会进入最终提示词。
- 模板卡片没有明显高度、换行或溢出问题。
- 用户忽略说明时，原有流程仍可使用。

### 阶段 B：建立研究台账

- 整理已经核验的游戏 UI、GPT Image 2 和 Nano Banana 资源。
- 记录许可证、真实案例和 Vistack 可借鉴范围。
- 不因此新增正式模板。

### 阶段 C：小批量词组试点

- 先选择 8–12 条能够独立生效的候选词组。
- 分别测试原提示词、加入词组后的结果和可编辑性。
- 通过试点后再决定是否扩大范围。

### 阶段 D：素材提醒原型

- 先制作最小数据结构和交互原型。
- 选择单参考和多参考模板各一个试点。
- 优先使用推荐提醒，不急于增加硬性阻断。

### 阶段 E：复盘与扩展决策

- 评估提醒是否打扰用户。
- 评估提示词是否因为追加词组而过长。
- 评估 GPT Image 2、Nano Banana 和已适配上游的兼容性。
- 根据实际结果单独批准、调整或放弃后续阶段。

## 候选影响范围

未来若相应建议获批，可能涉及：

- `src/types/index.ts`：少量可选模板提示字段。
- `src/components/StylePromptSelector.vue`：使用说明和候选素材提醒。
- `src/data/promptPhrases.ts`：经过测试的短词组。
- `src/data/promptPool.ts`：少量需要成段表达的约束块。
- 对应单元测试和必要的响应式界面测试。
- `docs/` 下独立的外部资源研究台账。

预计不涉及：

- 上游请求协议。
- 现有模板正文的批量迁移。
- 模板插入和自由编辑机制。
- 用户自定义词组机制。
- 未经明确批准的“游戏素材”模板新增。

## 风险与控制

- **模板变复杂**：所有新字段保持可选，先小范围试点。
- **提醒过度打断**：推荐提醒默认非阻断，并限制出现频率。
- **词组导致提示过长**：短词组与 Prompt Pool 分层，避免重复约束。
- **不同模型效果不一致**：候选词组在目标模型上分别测试，不假设跨模型完全等效。
- **外部内容许可证风险**：优先提炼方法并自行改写；许可证不明内容不复制正文。
- **研究内容误入私人菜单**：继续执行“游戏素材仅由用户明确指定准入”的硬规则。

## 评审清单

后续评审时需要逐项确认：

- 是否继续采用 `usageGuide` 作为第一阶段重点。
- 是否需要参考素材提醒，以及提醒出现时机。
- 第一批词组的范围和测试方法。
- 是否建立外部资源研究台账及其格式。
- 哪些阶段可以进入实施，哪些继续保留为建议。
- 每次新增“游戏素材”模板是否已经获得用户明确指令。

在以上事项获得单独确认前，本文保持“优化建议第一版，待评审”状态。
